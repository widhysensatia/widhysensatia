01 / Roadmap

Four phases. One controlled direction.

The rollout keeps the blast radius small: prove Bali, validate the data and stock lifecycle, replicate to Jakarta, then connect E-Commerce to the Main DC using Reservation / ATS.

1

Bali Pilot & Migration

Jubelio sync, Shop → DC/Warehouse, unified Web + Marketplace stock pool.

Replicate the proven Bali model with correct local warehouse routing.

4

Main DC Shared Stock / ATS

One physical stock source, controlled commitments through Reservation and ATS.

Design principles

Why this rollout is phased.

The goal is not only to ship integration code. The goal is to make every order, reservation, stock deduction, cancellation, and reconciliation explainable.

◎

Small blast radius

Bali is the pilot scope. Jakarta and Main DC remain downstream until Bali is proven stable.

⇄

One truth per phase

Each phase must have a clear inventory owner, transaction owner, and reconciliation path.

◌

No uncontrolled merge

Shared physical stock only works when demand is protected by reservation and ATS rules.

02 / Architecture shift

From separated channel stock to controlled shared inventory.

The near-term target is not Main DC yet. First, Bali Web + Marketplace should operate from one Bali E-Commerce DC source. Main DC shared stock comes only after both regions are stable.

Risk controls

The four failure modes to design around.

The difficult part is not transaction volume. It is preventing two workflows from making inconsistent promises about the same physical stock.

01

Double deduction

Retry or duplicate webhook must not deduct the same order twice.

02

Race condition

Concurrent Web and Marketplace orders must resolve against the same availability rule.

03

Event ordering

Cancel, fulfill, retry, and update events must be applied in a deterministic sequence.

04

Reconciliation gap

System balances must remain explainable against physical stock and transaction history.
