01 · Apa itu Guanta?

Platform untuk business process yang dibantu AI.

Guanta memosisikan produknya sebagai platform untuk membangun, menjalankan, dan memantau AI-driven processes—mulai dari agents hingga integrations, applications, scheduled execution, data, dan observability.

A

AI Agents

Prompt, knowledge, tools, objectives, dan execution boundaries yang bisa dikontrol.

↔

Integrations

API, CRM, ERP, internal tools, documents, browser automation, dan data pipelines.

▣

Custom Apps

Data model, screens, UI, business logic, workflow state, dan approval path bila proses membutuhkannya.

◷

Scheduled Process

Workflow bisa berjalan event-based atau terjadwal, tidak harus menunggu user membuka chat.

◎

Observability

Trace input, output, model, tools, latency, failure, review, dan business outcome.

⌁

Production Controls

Permission, retries, queues, secrets, human review, deployment controls, dan auditability.

Yang menarik: Guanta sendiri menekankan bahwa banyak workflow bisnis tidak membutuhkan agent untuk menjalankan semuanya. Trigger, validation, routing, retry, dan storage sebaiknya tetap deterministic; AI dipakai ketika understanding, extraction, reasoning, comparison, atau recommendation memang memberi nilai.
02 · Kenapa relevan?

PR/PO bukan cuma form. Ia adalah rangkaian keputusan dan data.

Waktu banyak terbuang untuk membaca request, melengkapi data, mencari histori pembelian, vendor, harga, lead time, approval, dan follow-up.

Manual-heavy

PR → Approval → Procurement → PO

  • User input kebutuhan manual.
  • Procurement cek kelengkapan.
  • Cari vendor / histori harga.
  • Susun PO.
  • Follow-up approval/status.
  • Banyak exception hidup di chat/manual context.
AI-assisted

Request → Structured draft → Approval → Execution

  • AI extract item, qty, needed date, purpose.
  • Sistem cek item master, stock, open PO, vendor, last price.
  • AI bantu draft PR / comparison / PO.
  • Human tetap approval keputusan penting.
  • Workflow deterministic menyimpan status dan audit.
  • Exception ambigu diarahkan ke manusia.

03 · Architecture principle

AI jangan menjadi orchestrator untuk semuanya.

Rule yang sudah jelas harus menjadi code/workflow biasa. AI masuk di titik yang membutuhkan language understanding, extraction, reasoning, atau recommendation.

Validation

Mandatory fields, quantity, permission, status transition, duplicate request.

Workflow

Trigger, routing, notification, retries, SLA timer, schedule, API/database writes.

Audit

Actor, timestamp, before/after, approval, document version, integration result.

Unstructured request

Extract kebutuhan dari email/chat/document menjadi data terstruktur.

Recommendation

Bandingkan stock, open PO, historical price, vendor, lead time.

Drafting

Draft PR/PO, comparison summary, reminder, dan exception summary.

Approval

Financial commitment tetap punya accountable human owner.

Exception

Harga tidak wajar, vendor baru, lead time kritis, compliance issue.

Override

Perubahan kritis butuh reason, permission, dan audit trail.

06 · Build vs Buy

Apa yang sebaiknya tetap di StockWizz?

Guanta bisa menjadi vendor candidate, tapi value langsungnya adalah sebagai benchmark architecture.

Build in StockWizz

Core workflow

PR/PO state, approval, permissions, inventory dependency, vendor records, audit trail, reports, dan company-specific business rules.

Platform candidate

AI runtime layer

Agent management, evaluations, tracing, model management, reusable connectors, observability, rapid AI app prototyping.

Hybrid

Likely sweet spot

StockWizz tetap source of truth/workflow engine; AI/service layer membantu extraction, comparison, recommendation, drafting, dan exception handling.

07 · Guardrails

AI procurement tanpa kontrol bisa lebih berbahaya daripada manual.

PO menyentuh uang, vendor, item, stock, approval, dan audit. Jadi “AI bisa” tidak sama dengan “AI boleh”.

Wrong recommendation / hallucination

AI tidak boleh menciptakan vendor, harga, stock, lead time, atau approval state. Fakta operasional harus berasal dari source data yang bisa ditrace.

Irreversible write action

Create PO, cancel purchase, mengubah approved price, atau mengirim dokumen ke vendor harus punya permission, validation, approval gate, dan audit trail.

Sensitive procurement data

Vendor pricing, finance data, negotiation, approval, dan credential integration perlu scoped access, secret handling, retention, dan due diligence.

Automation hides a broken process

Kalau approval matrix dan source of truth belum jelas, AI hanya mempercepat proses yang salah. Business rule harus dibersihkan dulu.

Lack of observability

Harus bisa dilihat input, sources, model/tool calls, output, failure, approver, dan business outcome.

08 · Kalau vendor benar-benar dievaluasi

Pertanyaan due diligence.

Mulai dari satu workflow nyata, bukan demo general.

Technical

  • Integration ke custom API / Mongo-backed app?
  • Approval gate dan idempotency untuk write action?
  • Secret management?
  • Deployment/self-host/control options?
  • Retry, queue, versioning, rollback?
  • Observability untuk prompt/tool/model changes?

Business / Governance

  • Pricing model?
  • Ownership atas workflow/code/config?
  • Data retention/privacy?
  • Exit strategy?
  • Dependency ke FDE setelah go-live?
  • Measurable outcome untuk pilot?
Conclusion untuk Michael
“Guanta menarik bukan karena sekadar AI agent, tapi karena mereka menggabungkan AI dengan business workflow, integration, scheduled process, control, dan observability. Untuk Sensatia, pattern ini bisa kita jadikan referensi: PR/PO core tetap deterministic di StockWizz, sementara AI membantu extraction, recommendation, vendor/price context, dan draft PO sebelum human approval.”

Next step yang paling masuk akal: pilih satu narrow pilot—misalnya request → Draft PR atau approved PR → assisted Draft PO—kemudian ukur time saved, error rate, exception rate, dan user acceptance sebelum diperluas.
