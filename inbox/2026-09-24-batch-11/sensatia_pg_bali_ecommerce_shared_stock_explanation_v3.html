Internal Architecture Note
24 September 2026
DC Padang Galak × Bali Ecommerce × Jubelio × Web Sales

Kalau stock disatukan, apakah secara sistem memungkinkan?

Ya — dari sisi volume transaksi dan kapasitas API, arahnya sangat memungkinkan. Tantangan utamanya bukan beban sistem, tetapi bagaimana menjaga reservation, urutan event, idempotency, dan source-of-truth agar Web Sales, Marketplace, dan refill retail tidak saling mengurangi stock dua kali atau menjanjikan unit yang sama.

Recommended direction
One physical stock di Padang Galak, lalu semua demand memakai logical reservation / Available-to-Sell. Bali Ecommerce tetap bisa menjadi area operasional pick-pack, tanpa harus menjadi inventory owner terpisah.

Migration implication

Ini adalah penjumlahan mentah. Angka business event unik kemungkinan lebih rendah karena satu transaksi bisa memunculkan PO + stock history sekaligus.

Worst-case API throughput
1,500–2,000 item-level operations/day masih sangat kecil.

Jika dipaksa menjadi HTTP request terpisah dan aktivitas efektif 12 jam, rata-rata hanya sekitar 2.1–2.8 request/menit. Published Jubelio API rate limit: 600 request/menit.

Feasibility: secara throughput, one-stock + ATS sync sangat feasible. Tetap perlu queue/backoff karena traffic nyata bisa burst, tetapi capacity bukan concern utama.

01
Double deduction

Marketplace event dipush balik ke Jubelio untuk movement yang sama.

02
Race condition

Web dan Marketplace reserve SKU yang sama pada waktu hampir bersamaan.

03
Out-of-order

Retry lama datang setelah event baru dan mengembalikan stock ke nilai salah.

04
Cancellation

Reservation release tidak kembali atau malah ter-release dua kali.

05
SKU mapping

Unmapped barcode membuat partial sync dan availability berbeda.

Design principle

Bali Ecommerce dapat tetap menjadi staging / pick-pack zone tanpa harus menjadi stock owner terpisah.

08

Rekomendasi rollout: jangan merge database dulu. Bangun kontrolnya, lalu kurangi fragmentation.

01 · Observe

Map stock domains

Trace warehouse stock vs shop stock, lalu PG/Pulo Gadung, Bali/Jakarta Ecommerce, Web Sales, Jubelio dan retail refill: siapa membaca dan menulis stock di mana.

02 · Instrument

Canonical event log

Normalisasi event lintas warehouse stock dan shop stock; tambahkan event_id, origin, reference, warehouse, delta, sync status dan reconciliation.

03 · Shadow

Calculate ATS only

Hitung ATS PG tanpa mengubah live Jubelio. Bandingkan hasil beberapa hari.

04 · Queue

Outbox + retry

Push ATS melalui queue dengan idempotency, ordering, backoff dan error visibility.

05 · Pilot

Selected SKUs

Uji Web + Marketplace + Retail refill bersamaan pada SKU terkontrol.

06 · Simplify

Retire artificial pool

Setelah stabil, ubah Bali Ecommerce menjadi operational zone dan kurangi PG→Ecom stock transfer.

Saran akhir: lanjutkan direction one-stock. Data volume menunjukkan beban teknis kecil; manfaat simplifikasi cukup besar. Tetapi go-live hanya setelah reservation/ATS, origin-aware sync, dan reconciliation berjalan stabil.
