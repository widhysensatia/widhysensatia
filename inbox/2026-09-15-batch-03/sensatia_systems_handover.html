Governance & Documentation Rules

What counts as a completed handover.

Readiness Model

Explained → Documented → Access Ready → Practiced → Verified

Explanation alone is not transfer.

Definition of Done

  1. Colin explains current behavior.
  2. Documentation and evidence exist.
  3. Access is available and recoverable.
  4. Widhy performs the work independently.
  5. Reviewer verifies the result.
  6. Normal execution no longer depends on Colin.

Jubelio target recovery behavior

Direction: StockWizz event → exact SKU resolution → Jubelio item/location → stock adjustment.

  • Successful items are not repeated.
  • Failed items retry separately.
  • StockWizz quantity is not changed again during retry.
  • Failures remain visible if retry still fails.
  • Manual adjustment remains possible.
  • Final reconciliation must be verifiable.
Payment provider documentation requirements

Incident Response Standard

Symptom → Scope → Evidence → Diagnosis → Safe Action → Verify → Reconcile → Document

Stock Integrity
1. Identify item/location. 2. Capture stock. 3. Review history. 4. Identify originating transaction. 5. Check duplicate/wrong/missing movement. 6. Preserve evidence. 7. Controlled correction. 8. Reconcile.
Website Checkout / Payment
Capture identifiers → provider status → pending/final order → webhook/logs → prevent duplicate fulfilment → refund/recovery → root cause.
Jubelio Sync
Identify PO/restock → per-item status → SKU/location mapping → quantity payload → retry failed only → manual fallback → reconcile.
Performance
Reproduce → browser/network → API duration → Better Stack → DB query/indexes → N+1/repeated calls → compare before/after.
Deployment Failure
Stop changes → capture evidence → assess impact → rollback if needed → verify → communicate → post-incident notes.

Handover Control Center

How explanations become verified capability.

Working Rules

  • One session = one primary focus.
  • Every session creates documentation output.
  • Unresolved items go to Knowledge Gaps.
  • Capability is tested by reverse handover.
  • Jira = work tracker.
  • Notion = system knowledge, evidence and readiness.

Simple Workflow for Colin

  1. Find the correct existing page.
  2. Replace unknowns with verified current-state info.
  3. Preserve confirmed vs uncertain boundary.
  4. Record unresolved items.
  5. Widhy performs reverse handover.
  6. Reviewer verifies result.
One topic = one permanent source of truthIf a new system/domain does not fit clearly, use New System / Domain Intake temporarily. Avoid fragmented pages like “Colin Notes” or “Deployment Info 2”.
KT Session Template
Session date/topic/trainer/owner/Jira/docs; goal; current understanding; Colin explanation; architecture/flow; important files/modules/services; access; live walkthrough; safe/unsafe actions; documentation updated; reverse-handover task/result/review; capability status; open questions; next action.
New System / Domain Intake
Temporary holding area only. Promote to a permanent page only when the topic is a distinct system/service/domain, cannot fit an existing source-of-truth page, and has enough operational importance or complexity to justify dedicated ownership.

Assessment & Recommended Next Actions

Synthesis from the current structure, tracker and knowledge-gap data.

What is already strong

  • Clear domain-based source-of-truth structure.
  • Confirmed vs unknown evidence is explicitly separated.
  • Security rules exclude actual secrets.
  • Reverse handover is part of Definition of Done.
  • Jira vs Notion responsibilities are clear.
  • Incident patterns exist at framework level.
  • New-domain intake reduces documentation fragmentation.

Main risk right now

The structure is ahead of the operational content. The highest risk is missing verified production details, recoverable access, tested deployment/rollback, tested backup restore, and populated infrastructure/integration/runbook registries.

Recommended execution order

  1. Complete access & ownership
    GitHub, hosting, DB, domain/DNS, observability, auth/payment/providers and recovery ownership.
  2. Map production infrastructure
    Provider/resources/regions/environments/admin/billing/domain/DNS/SSL/recovery.
  3. Verify system & repository landscape
    All active, legacy and deprecated systems, repos, workers, scripts and services.
  4. Complete StockWizz + website architecture walkthroughs
    UI → API → DB → jobs → integrations; CMS and payment/order lifecycle.
  5. Run deployment & rollback reverse handover
    Widhy performs real controlled steps under review.
  6. Prove backup / restore capability
    Restore in a safe isolated environment and retain evidence.
  7. Populate empty registries
    Infrastructure, Integrations and Incident Runbooks should become operational tools.
  8. Close with capability verification
    Move Planned → Explained → Documented → Access Ready → Practiced → Verified only with evidence.
Operating principleMeasure handover by repeatable capabilities, not meeting count: deploy, rollback, trace requests, diagnose incidents, reconcile stock, recover access, restore data and operate integrations safely.
